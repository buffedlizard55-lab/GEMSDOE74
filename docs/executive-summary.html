Resolution of "Predicted values must be in range [0, 1]"

The common portal rejection Predicted values must be in range [0, 1] arises from two distinct mechanisms:

  1. Float32 Sentinel Leakage: Unmasked nodata cells in raw GeoTIFF inputs contain -3.4028235e+38. If copied into predictions, the global raster minimum is negative, causing immediate rejection.
  2. NaN Outside Footprint: If outside-footprint cells are encoded as NaN, portal validators running standard NumPy min/max checks without NaN masking report invalid ranges.

Permanent Fix: In the primary submission file, all outside cells are explicitly written as 0.0 with nodata=None. All cells within the footprint are strictly clipped to [0.0, 1.0]. The file is reopened byte-by-byte to guarantee zero NaNs, zero infinities, and all values in [0, 1].
