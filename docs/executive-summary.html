Before you upload any file

  1. Use the output from a validated model built from authorized competition inputs. Do not submit a synthetic demo, historic review TIF, or file whose source/rights are unverified.
  2. Confirm the file is a single-band 32-bit float GeoTIFF, in EPSG:32611 at 100 m, with the exact CRS, shape, bounds and geotransform of the official sample submission. Use its exact outside-bounds mask; the official problem page specifies null or NaN outside bounds.
  3. Re-open the bytes after writing. Confirm there are no NaN or infinite values inside the footprint, all prediction values lie in [0,1], and CRS/shape/transform match. Keep the validation receipt and SHA-256 beside the candidate.
  4. Confirm the candidate passed the project holdout protocol, leakage canary, and registry uniqueness check, with a same-holdout incumbent comparison. This is a separate gate from GeoTIFF format validation.

DrivenData form steps (once a file is cleared)

  1. Sign in to the DOE GEMS Prize competition.
  2. Open the competition's submission form and select File to submit. Choose the one-band .tif, or a .zip containing exactly one GeoTIFF if the form accepts that format.
  3. Review the upload's validation response. If it reports values outside [0,1], stop: do not patch the file by guessing. Re-open it and locate NaN, infinity, nodata sentinels, or values outside the allowed range. Also re-check geometry against the official sample.
  4. Use the optional Note to identify the experiment. Suggested note for the proposed C1 experiment (not an existing result; 96 characters): C1 magnetic edge artifact suppression; HOLD pending official-data holdout and format validation.
  5. Submit only after the project status changes to OK TO SUBMIT based on a complete run card and a real candidate file. Save the submission-page receipt. That receipt is the only source of an organizer-confirmed result.

Why the old range error must be checked, not assumed fixed

The official page requires prediction values between 0 and 1 and specifies null/NaN outside the raster bounds. A NaN or a nodata sentinel may cause a range failure if the portal treats it as a prediction value. A zero-filled exterior avoids non-finite range values but may conflict with the stated outside-bounds encoding. Therefore use the official sample's geometry/mask and test the exact output with the organizer's validator where available. This repo does not claim the historic TIFs resolve that policy question for a future model.
