The file you upload

The submission is a single-layer GeoTIFF that must meet the rules below. The problem page sets the format.

CRS
EPSG:32611, WGS 84 / UTM zone 11N (epsg.io/32611; central meridian −117°, false easting 500 000, scale 0.9996, metres)
Resolution
100 m
Bounds
Same as the training data. Data outside the bounds is null or NaN.
Layers
One band
Type
float32
Values
Between 0 and 1, the confidence or probability of fault presence
Shape
3730 rows × 3292 columns. Taken from GEMSDOE32's receipts; to be confirmed against the official header.

Source: problem page, "Submission format".

Steps

  1. Check eligibility first. Individuals must be U.S. citizens or permanent residents. DOE and FFRDC staff have restrictions, and FCOC-owned entities are excluded. Read rules §1.3 before you register. Source: official rules.
  2. Register on DrivenData and accept the rules. You need an account to download the training features and labels.
  3. Get the training features. They are login-gated. Download them yourself and place them in data/, which is git-ignored. Do not commit them.
  4. Produce a prediction raster on the competition grid. The pipeline that does this is not yet built, because it needs the features from step 3.
  5. Validate the file. Run python scripts/validate_submission.py your_file.tif. It exits with status 0 only when every check passes. Confirm the grid against the official header first.
  6. Name it and write a note. Use a unique name, for example gems74-<method>-<YYYYMMDD>-<hash8>, which the writer enforces by regex. Write a short note (the repo keeps it under 140 characters). The form's real note limit is not confirmed (IR-74-13).
  7. Disclose AI use in the narrative. The rules require you to state in the narrative the extent to which generative AI was used and how, not counted in the word count. Rules §3.2.
  8. Upload and submit. Use the upload control on the DrivenData submission page. You may submit up to three times per week. Rules §3.2.
  9. Choose one final submission before the deadline. Each entity gets one final submission, selected before the deadline. Rules §3.4.

Checklist before you press submit

  • ☐ validate_submission.py passes, with the grid confirmed against the official header.
  • ☐ Name and note are written. The note is under the form's limit.
  • ☐ The narrative discloses generative-AI use (rules §3.2).
  • ☐ The file's sha256 is recorded in the run card.
  • ☐ The submission is not a copy of another team's file (the brief requires a unique submission).
  • ☐ The file does not contain any third-party data you are not licensed to share (rules A.5). Public-domain and CC BY 4.0 inputs need attribution in the narrative.
  • ☐ Submission materials may become public (rules A.4), so the note contains nothing confidential.
