NEGATIVE / HOLD

Do not submit either checked-in TIFF

This review found that H74-1 is a synthetic fixture, H74-A has unverified sibling-mirror provenance, and the former generator/holdout code fabricated evidence fields. Their format can be inspected locally, but their spatial predictions are not supported by official inputs or a compliant holdout. The top-level page and executive summary have been corrected to say this plainly.

Line-by-line findings (repository facts)

  1. Competition data absent. `data/README.md` says the folder is a placeholder; the inventory contains only README and `.gitkeep`. This review did not obtain login-gated DrivenData files. The official data tab is here.
  2. Generator was synthetic, not a training/inference pipeline. In the previous `scripts/generate_submission.py`, `build_h74_1_field()` created synthetic depth and elevation; code made a synthetic catalogue and hidden truth and then emitted dots. It did not read the competition feature stack. That implementation was replaced with a fail-closed entry point. Running it now exits 2 and writes no candidate.
  3. Holdout was not protocol-compliant. The prior evaluator hid random catalogue pixels in quadrants; the segment-named version labeled connected pixels and explicitly disabled its collar. Neither rebuilt catalogue features from visible segments or used the required buffered whole-segment hide-and-recover. Both entry points now exit 2 without writing evidence.
  4. Hard-coded leakage/registry metrics. The former generator inserted `AUC=0.68`, `rho=0.42`, and `overlap=38.2%` directly into its run report. They were not measured there. Those historical numbers are excluded from the current run card; no registry rasters are present to reproduce correlation or overlap.
  5. Canary test was a false assurance. `tests/test_canary.py` returned successfully when its optional local data were missing, and its old random-pixel split was not the required holdout. It now tests only that the helper catches a deliberate label-copy feature; this is a software unit test, not a real-data leakage result.
  6. Old release pages contradicted themselves. The overview top panel said HOLD, while lower hero content and the executive summary said ready/OK to submit. Those pages now consistently say DO NOT SUBMIT and classify existing TIFs as review fixtures.
  7. Format inspection is narrower than release validation. The local validator reopened H74-1 zeros TIFF and returned exit 0; it reported one band float32, 3292×3730, EPSG:32611, expected pinned transform, all stored values finite and in [0,1], nodata unset, and 35,641 positives. Its catalogue check was skipped (`/tmp/gems74_data/labels.tif` absent). The official template itself is also absent, so template match and real footprint correctness remain unknown.
  8. Score attribution is unproven. No organizer receipt in this repo connects `h33-h33-2-b2` to the stated 0.2778. Sparse predictions could plausibly interact favorably with distance-weighted Tversky, but the specific causal explanation needs the original raster, exact evaluator and receipt. Repository prose previously overstated that explanation; README now labels it a hypothesis.
  9. Leaderboard numbers conflict by date/source. The user prompt includes 0.3195 as current high. The committed dated snapshot `docs/review/data/leaderboard_2026-10-21.json` records 0.4413 at rank 1 and 0.2778 at rank 47. This review did not independently fetch the live page; treat the JSON as a dated repository snapshot, not a live feed. Recheck the official leaderboard before citing current rank.
