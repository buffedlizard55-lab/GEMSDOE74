How overlap was checked

We cloned buffedlizard55-lab/GEMSDOE32 at commit 98901f3 and ran case-insensitive grep -ril over its working tree (excluding .git). Each count is the number of files containing the term. A term with zero files is treated as not covered. A term with many files is treated as covered, even if its exact method differs. Counts are file counts, not evidence that a method is equivalent.

The four candidates

C1. Flight-line-artifact-suppressed magnetic edges  RANK 1 · LOW COST

Layers
Magnetic bands in the official stack (RTP, TMI, and their gradients), with the GeoDAWN acquisition geometry from USGS metadata.
Physical signature
Horizontal-gradient maxima that survive after an oriented notch removes the survey-line periodicity. Target: contacts from fault-related magnetic contrast that the periodic artifact masks or imitates.
Why it should catch an unlisted fault
The USGS summary gives the geometry: flight lines at azimuth 90° (east–west), spaced 200 m apart in Area 1 and 400 m in Area 2 (ScienceBase). The contractor already applied tie-line leveling and micro-leveling to the magnetic data, so any remaining line-periodic residue is what this test looks for. That residue may be small. The hypothesis is that it is still strong enough to affect edge maps. It is a test to run, not an assumption.
Named non-fault mimic
Residual line-periodic leveling artifacts after the contractor's corrections, and lithologic contacts (intrusive or volcanic margins) that give edges with no displacement.
Difference from GEMSDOE32
GEMSDOE32 computes gradient-magnitude edges (tmi_edge, rtp_edge) but has no survey-geometry or notch step. Overlap: the edge feature family is shared, so C1 is only new if the notch changes the edges. That is the test.
Trade-off
A notch at the line-spacing wavenumber may also remove real signal at the same wavelength. The holdout must check that.
Expected gain (judgement)
Medium. Not estimated numerically.
Implementation cost
Low. One FFT notch on the magnetic bands, then gradients.
Data status
Inside the official stack, once obtained. USGS metadata verified.
Validation gate
NOT RUN Run the holdout with and without the notch. Keep the change only if it beats the incumbent holdout score under the same evaluator.

C2. Survey-coverage prior on where experts can label faults  RANK 2 · VERY LOW COST, WEAK ALONE

Layers
No physical layer. The GeoDAWN survey-area and flight-geometry metadata (Area 1 vs Area 2; flight height 100–150 m vs 150–200 m; line spacing 200 m vs 400 m).
Physical signature
None. This is a labelling-process hypothesis: the hidden labels come from expert review of the data, and experts can map faults more reliably where the data resolve them.
Why it should catch an unlisted fault
If the expert labels cluster where the survey resolves structure, a prior that weights emission by survey resolution should raise the credit per dot. This is a bet on the labelling process, not on geology.
Named non-fault mimic
Sampling bias: lithium and brine exploration around Clayton Valley (Area 1, per USGS) draws both data and attention. That bias would look like a fault prior.
Difference from GEMSDOE32
Not covered: no survey-area or line-geometry wording in its code or notes.
Expected gain (judgement)
Low to medium, and unsafe alone.
Implementation cost
Very low.
Data status
USGS metadata verified. The labels' spatial distribution has to be checked against the official data.
Validation gate
NOT RUN A catalogue holdout cannot test a labelling-process prior by itself. Use it only as a weight on C1 or on another candidate, and test the weight on a holdout split by survey area.

C3. Multi-azimuth phase-congruency scarp detection on 1 m DEM  RANK 3 · MEDIUM-HIGH COST

Layers
1 m DEM, which the competition says users may need (rules §3.3). The DEM link list has not been obtained, so its coverage is unverified.
Physical signature
A linear step that stays coherent across illumination azimuths. Phase congruency is largely invariant to illumination direction, so a scarp shows at every azimuth and a shadow edge does not.
Why it should catch an unlisted fault
Small surface scarps under vegetation can be too weak in 100 m features but still coherent in 1 m data. If the expert labelling used the 1 m lidar (the competition text does not say so, so this is an assumption to check), such scarps are plausible labels.
Named non-fault mimic
Roads, canals, fence lines and railway embankments; stream-terrace risers; aeolian dune margins.
Difference from GEMSDOE32
Method differs: GEMSDOE32 uses curvature and ridge filters. Target overlaps heavily: "scarp" appears in 44 of its files, so C3 is a method change on a covered target.
Expected gain (judgement)
Medium, with high overlap risk.
Implementation cost
Medium-high. The 1 m tiles are large and have not been obtained.
Data status
The competition refers to USGS 1 m DEM tiles (rules §3.3). The tile list was not obtained in this environment.
Validation gate
NOT RUN Only after C1 is tested.

C4. Hypocentre planes from 3-D earthquake locations  RANK 4 · MEDIUM COST, PARTIAL OVERLAP

Layers
Earthquake locations (USGS Comprehensive Catalog, free and official), used in 3-D rather than as the 2-D density already in the stack.
Physical signature
Planar alignments of hypocentres at consistent depth and dip, which can mark active fault planes.
Why it should catch an unlisted fault
Microseismicity can locate a fault that shows no surface scarp, so it can reach concealed faults.
Named non-fault mimic
Induced seismicity from fluid injection or extraction, and quarry or mine blasts, both of which produce planar clusters with no tectonic fault.
Difference from GEMSDOE32
Partial overlap: seismicity (19 files), earthquake (17) and ComCat (12) appear, and hypocentre appears in 5 files. The 3-D planar step is not verified as present.
Expected gain (judgement)
Low to medium.
Implementation cost
Medium. Needs the ComCat download, which this environment cannot reach.
Data status
Official and free, but not obtained here.
Validation gate
NOT RUN

Gate for all candidates

No submission slot is spent on any candidate until it beats the incumbent on our holdout. Until we have the feature stack, the incumbent is undefined, so the first task is to build it. The holdout must withhold whole fault segments, with a buffer, derive all catalogue-based features from the visible faults only, and mask visible faults pixel-exactly.
